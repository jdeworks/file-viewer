## Risks

- **Cache contamination can create false offline passes.** Mitigation: unique fresh browser contexts, explicit service-worker/cache cleanup, separate limited/full runs, and cache-key assertions.
- **A screenshot can hide delayed renderer failures or blank nested canvases.** Mitigation: wait for type-specific landmarks and stable dimensions, capture console/page errors, inspect actual preview/canvas/image contents, and retain individual shots.
- **The 45 selected examples can overrepresent tiny synthetic fixtures.** Mitigation: prioritize distinct render paths and supplement with richer checked-in examples where a tiny fixture cannot demonstrate layout/scrolling meaningfully; disclose fixture limitations.
- **Visual coverage can become shallow across many formats.** Mitigation: require written per-shot observations and explicit failure modes, not only generated image files.
- **Offline service-worker version testing can accidentally modify release files.** Mitigation: test a copied temporary `docs/` tree or a controlled response shim; never leave a synthetic version in tracked source.
- **Companion testing is locally destructive by design.** Mitigation: generated temp root/config/token, path assertions before every delete, root-delete refusal proof, port ownership check, and unconditional cleanup.
- **CORS is not authentication for local programs.** Mitigation: report it as a browser-origin boundary, separately test token requirements for mutations, and avoid overstating the security model.
- **WSL2 may not represent packaged Linux/Windows desktop behavior.** Mitigation: attempt real Tauri launch, report the exact gap, and do not translate source/build success into tray/native-picker runtime coverage.
- **Chromium can miss Firefox/WebKit regressions and browser-specific private-network rules.** Mitigation: report the engine limitation, supplement when feasible, and keep production HTTPS-to-loopback behavior as an explicit risk unless directly proven.
- **A hostile CORS request can mutate state even when its response is unreadable.** Mitigation: negative tests assert server status and unchanged disposable filesystem/config, not merely browser read failure.
- **The full gate is long and may expose unrelated pre-existing failures.** Mitigation: capture baseline/final results, isolate reproducible failures, and fix only release-impacting in-scope defects while reporting other risks.
- **Generated artifacts can mask source drift.** Mitigation: record pre/post diffs and run generators plus final full gate from the final source tree.
