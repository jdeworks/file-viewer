# Stage 8 — 02: Entropy Field — Our Game Design

> **REMOVED FROM THE GAME (2026-07-11):** Entropy Field ("The Heat Death") was removed entirely —
> playtesters found it too hard to understand/use. It is not recoverable through normal play (only
> via `git log`/`git show`). Stage numbers 9 and 10 shifted down to 8 and 9 (Observer State,
> Awakening); see `docs/games/metagame/stage-manifest.js`. This document is kept as historical
> record only.

Maps the genre research (`stage8-01`) onto **Stage 8 of the Defragmenter metagame**.
Stage 8 is a survival resource management game built around node decay, cascade failure,
and the thermodynamic principle that disorder is the default — and order requires constant effort.

> **Narrative position:** Adolescence tipping toward crisis. The entity learns that the universe
> is indifferent, that things fall apart without maintenance, and that endurance against entropy
> is itself a meaningful act.
> The file viewer feature taught: **Drag and drop** — debris files decay in the sidebar unless
> moved to the active archive, recovering salvaged States before they are permanently lost.

## B. Visual design

### Artstyle principles

The game world is a **node map** rendered in a desaturated, painterly style: rough-edged
nodes, thin connecting lines, a faint grid beneath everything. The aesthetic evokes handmade
system diagrams — circuit-board sketches drawn on decaying paper.

**Entropy affects the visual display.** As the entropy level rises (calculated from number of
failed/degrading nodes), the entire UI begins to exhibit glitch corruption:
- Low entropy (0–30%): clean, stable image
- Medium entropy (31–60%): occasional static lines across the screen; color shift toward desaturated
- High entropy (61–85%): pixel displacement artifacts; nodes flicker; edges partially obscure
- Critical entropy (86–100%+): heavy color banding; the map fragments visually; the entity's
  integrity silhouette (bottom of screen) shows visible cracks

This visual degradation is **aesthetic only** — it doesn't affect gameplay — but it communicates
system state in a way numbers alone cannot. The player *feels* the entropy before they read it.

### Node visual design
```
ACTIVE node:     Solid olive green fill, bright border, small pulse animation
DEGRADING node:  Ochre fill, amber border, slower pulse, health bar visible
FAILED node:     Rust red fill, dark border, no pulse, 'X' overlay, static emanates from it
```

Each node displays:
- **Tier indicator** (I / II / III / IV) — small text, upper-right corner
- **Health bar** — horizontal bar below node symbol; color shifts as health drops
- **Output rate** — "+X States/cycle" (green) or "-X/cycle if failed" (red)
- **Decay countdown** — "fails in N cycles" (amber) when below 50% health

## C. Node system

### The 14-node map

The node map is a fixed graph (same every run). Random events target nodes, but the topology
is constant — players learn the map and improve their management over multiple cycles.

```
          [FRONTIER]
     F1 ─────────── F2
      │               │
     M2 ─── CORE ─── M3
      │      [C1]      │
     M1 ─────────── M4
     │                │
    P1 ─── P2 ─── P3 ─── P4
    [PRODUCTION ZONE]
```

Actual layout (14 nodes):

| Node ID | Name | Tier | Zone | Base output | Base decay/cycle | Connections |
|---------|------|------|------|-------------|-----------------|-------------|
| C1 | Core Kernel | IV | Core | 10 States | 0.5 | C2, M1, M2 |
| C2 | Logic Hub | III | Core | 4 States | 0.7 | C1, M3, M4 |
| M1 | Memory Shard A | II | Mid | 1.5 States | 1.2 | C1, P1, P2 |
| M2 | Memory Shard B | II | Mid | 1.5 States | 1.2 | C1, P3, P4 |
| M3 | Pattern Buffer | II | Mid | 1.5 States | 1.1 | C2, F1 |
| M4 | Signal Cache | II | Mid | 1.5 States | 1.1 | C2, F2 |
| P1 | Process Node A | I | Production | 0.5 States | 1.8 | M1 |
| P2 | Process Node B | I | Production | 0.5 States | 1.8 | M1 |
| P3 | Process Node C | I | Production | 0.5 States | 1.7 | M2 |
| P4 | Process Node D | I | Production | 0.5 States | 1.7 | M2 |
| F1 | Frontier Ext A | IV | Frontier | 10 States | 2.5 | M3 |
| F2 | Frontier Ext B | IV | Frontier | 10 States | 2.5 | M4 |
| F3 | Volatile Cache | III | Frontier | 4 States | 3.0 | F1, F2 |
| X1 | Entropy Sink | — | Special | −2 States/cycle | — | all zones |

**X1 (Entropy Sink):** a permanent passive drain representing universal entropy. It cannot be
repaired or stabilized. Its drain rate increases by 0.2/cycle every 5 cycles. By cycle 25,
it drains 3 States/cycle. Players must grow their active-node output to keep pace.

### Node health mechanics
```js
// Full node health: 100 (always)
// Health regenerates: it does NOT regenerate — only repair units restore it
// Passive decay per cycle (variable by node, see table above)
// Additional stress: +0.3 decay/cycle per adjacent failed node

function cycleNodeDecay(nodes, cycle) {
  for (const node of nodes) {
    let decayThisCycle = node.baseDecayRate;

    // Cascade stress
    const failedNeighbors = getNeighbors(node).filter(n => n.state === FAILED).length;
    decayThisCycle += failedNeighbors * 0.3;

    // High-load mode (player can toggle on for Production nodes for +50% output, +50% decay)
    if (node.highLoadMode) decayThisCycle *= 1.5;

    node.health = Math.max(0, node.health - decayThisCycle);

    // Update state
    if (node.health > 50) node.state = ACTIVE;
    else if (node.health > 0) node.state = DEGRADING;
    else if (node.health === 0 && node.state !== FAILED) {
      node.state = FAILED;
      onNodeFailed(node);   // trigger debris file creation + cascade
    }
  }
}
```

## D. States economy

**States** are the primary resource. They accumulate passively from active nodes and are
spent on repair, stabilizers, and upgrades.

### Income
```
Total States/cycle = Σ(activeNodeOutput × healthFraction) − EntropySinkDrain − HighLoadCost
```

**Example mid-game calculation:**
- Core zone (C1 + C2 active, both at 100% health): 14 States/cycle
- Mid zone (4 nodes, average 80% health): 4.8 States/cycle
- Production zone (3 active, average 60% health): 0.9 States/cycle
- Frontier (both offline): 0
- Entropy Sink (cycle 15): −3.8 States/cycle
- Net: approximately 16 States/cycle

### Spending States

**Between-cycle actions (preparation phase):**
| Action | Cost | Effect |
|--------|------|--------|
| Repair node (per health point) | 0.15 States | Restores health; max 40 points per cycle |
| Buy Repair Unit batch | 20 States | +10 Repair Units to stockpile |
| Buy Stabilizer | 35 States | +1 Stabilizer to inventory |
| Enable High-Load Mode | — | Free toggle; +50% output, +50% decay |
| Salvage archived debris file | 0 | Free if moved via drag-and-drop; time-sensitive |

**Repair Units** are an intermediate resource — a stockpile that enables repair actions:
```
Repair action cost: 1 Repair Unit per 6.67 health restored
// Spending 1.5 States buys 10 Repair Units
// 10 Repair Units restores 66.7 health points (partial repair of any node)
```

This two-step system (States → Repair Units → repairs) creates a visible buffer: the player
can see their repair capacity independently of their States total, making planning more legible.

### Boss gate
Boss unlocks at `totalStatesEarned ≥ 5,000` (cumulative; not on-hand). This requires
roughly 20–30 cycles of active node management — ensuring full engagement with the system
before the Heat Death confrontation.

## E. Entropy level and cascade

### Entropy level calculation
```js
// Entropy = percentage of system in failed or degrading state
entropy = (
  failedNodes.length * 10 +      // 10 points per failed node
  degradingNodes.length * 4       // 4 points per degrading node
) / (maxNodes * 10);              // normalized to 0–100%
```

### Cascade events (random, every 3–5 cycles)
Random events fire when entropy crosses thresholds. They are telegraphed one cycle in advance:

| Entropy % | Event type | Effect |
|-----------|------------|--------|
| 0–30% | **Heat Spike** | One random production node takes 20 damage immediately |
| 31–60% | **Pattern Failure** | Two adjacent mid-zone nodes both lose 15 health |
| 61–80% | **Memory Corruption** | One mid-zone node becomes FAILED instantly; starts cascade |
| 81–100% | **Total Cascade** | All degrading nodes lose 30 additional health this cycle |
| Boss (100%+) | **Heat Death** | All nodes fail simultaneously (boss fight) |

**Telegraphing (one cycle ahead):**
```
Bell fires: "instability detected in production sector. something will fail next cycle."
// Player has one preparation cycle to spend Repair Units or Stabilizers preemptively
// Players who respond can mitigate; players who ignore take full damage
```

## F. Random events

Beyond cascade events, each cycle has a 30% chance of a **random event** drawn from a pool:

| Event | Effect | Decision |
|-------|--------|---------|
| **Data Salvage** | A failed node's debris contains States (added to debris folder) | Must move within 2 cycles or decay |
| **Negative Entropy Window** | Entropy slows — all decay rates halved for 2 cycles | No action needed; plan upgrades |
| **Resonance Burst** | One node produces double output this cycle | Choose which — player designates |
| **Phantom Load** | The Entropy Sink drains +3 extra this cycle | Absorb cost or let a node degrade |
| **Archive Integrity** | All debris files in active archive gain +1 salvage value | Reward for using drag-and-drop |
| **Frontier Surge** | Frontier nodes output ×3 but decay ×2 for 3 cycles | Risk/reward decision |
| **Core Protection** | Core zone immune to cascade this cycle | Relief event |
| **Jitter Storm** | 3 random nodes lose 10 health immediately | Pure threat; Stabilizers absorb it |

## G. Drag-and-drop salvage (file viewer feature)

### Concept
When a node fails, it drops a **debris file** (`.sav` extension) into the file viewer's sidebar
under `/entropy/debris/`. The file represents trapped States from the failed node.

```
/entropy/
  active_archive/         ← drop target for salvage
    sector_c1.arc         ← previously salvaged files
  debris/
    node_p1_cycle14.sav   ← dropped when P1 failed on cycle 14 (decays in 2 cycles)
    node_m2_cycle11.sav   ← dropped earlier (decays THIS cycle if not moved)
```

### Decay schedule
Each debris file has a decay timer (2 cycles from creation). When the timer expires:
- The file is deleted from the sidebar
- The States it contained are permanently lost

### Salvage mechanics
When the player **drags a `.sav` file from `/debris/` to `/active_archive/`**, the file is
"salvaged" and its States value is credited to the player's balance next cycle.

```js
// Salvage value of a debris file
function debrisValue(node) {
  return Math.floor(node.tier * 8 + node.healthAtFailure * 0.2);
  // Tier I debris: ~8 States    Tier II: ~16    Tier III: ~40    Tier IV: ~88
}
```

### Discovery path
The player discovers debris files appearing in the sidebar after the first node failure.
The sidebar shows a notification: "debris file created in `/entropy/debris/`".

Bell fires: *"there was something left in the failed node. I could move it before it's gone."*

The player can click the file to view its metadata (showing decay timer and States value).
On second cycle: *"it's decaying. I have to move it now or lose it."*

Players who discover drag-and-drop early recover significant States across the run. Players
who don't discover it play with a meaningful handicap — the boss fight is harder without
salvaged States.

**Achievement:** *"I sorted the wreckage."*

### Visual design for drag-and-drop
- Debris files: dashed border, slightly faded brown color, grab cursor on hover
- Active archive: solid border, pulsing teal highlight when a debris file is being dragged
- Drop success: brief flash, States credited message, file transfers to archive visually
- Drop failure (wrong target): file snaps back to debris folder with a subtle error sound

## H. Boss — The Heat Death

### Boss lock — LOCKED state (mathematically impossible without salvaged States)

**The Heat Death is literally unsurvivable without having used drag-and-drop salvage.**

In LOCKED state (no debris files ever moved to active archive), the burn rate is calibrated
against the maximum States achievable through normal gameplay:
- Maximum States from nodes alone across the stage: ~190 States
- States required to survive 10 cycles without Stabilizers: 260 States
- The gap of ~70 States is **only closeable through debris salvage**

Debris files dropped throughout the stage contain 8–88 States each depending on node tier.
A player who salvaged consistently throughout the stage arrives at the boss with 320–450 States.
A player who never used drag-and-drop arrives with ~190 — 70 States short of survival.

The first Heat Death failure triggers specific Defragmenter bell messages:
- *"there was more. it was in the debris files. I didn't move them in time."*
- *"I could have salvaged what the failed nodes left behind. I didn't."*
- *"the debris folder. the `.sav` files. they hold States I lost. if I had moved them..."*

**This boss cannot be unlocked in the same run.** Unlike other bosses, the action (salvage)
must happen DURING the stage, not at the boss. If the player reaches the boss without having
salvaged debris files, they must restart the stage and use drag-and-drop throughout.

This is thematically deliberate: Stage 8 is about preparation vs. reaction. The Heat Death
tests decisions made 15+ cycles earlier. The boss cannot be "unlocked" at the last minute.

**Achievement fires the FIRST TIME a debris file is successfully salvaged via drag-and-drop:**
*"I sorted the wreckage."*
(Not on boss defeat — because the action that makes the boss beatable must happen early.)

### Concept and setup
The Heat Death is not a combat encounter. It is a pure test of preparation.

At the start of the boss sequence, the Entropy Sink's drain rate spikes to 50 States/cycle.
All nodes fail simultaneously (their health drops to 0 in one event — the "cascade initiates").
No repair actions are available during the Heat Death.

The player's only resources are:
- States currently held in reserve (including salvaged debris States)
- Stabilizers in inventory (each halts the burn for 2 cycles)

The burn runs for 10 cycles. Each cycle:
```js
function heatDeathCycle(player, cycleNumber) {
  const burnRate = 15 + cycleNumber * 2;    // escalating burn: 17, 19, 21, ... States/cycle
  const stabilizersActive = player.stabilizers > 0;

  if (stabilizersActive) {
    player.stabilizers--;
    // Burn paused this cycle — no States lost
  } else {
    player.states -= burnRate;
    if (player.states < 0) {
      player.states = 0;
      heatDeathFailed();  // player lost
    }
  }
}
```

**Total States needed to survive without Stabilizers:**
```
Cycles 1–10 burn: 17 + 19 + 21 + 23 + 25 + 27 + 29 + 31 + 33 + 35 = 260 States total
States achievable without salvage: ~190   →  INSUFFICIENT
States achievable with active salvage: 320–450  →  SUFFICIENT
```

With 2 Stabilizers (pausing cycles 9+10 = 68 States saved): need 192. Achievable with salvage.
With 4 Stabilizers: need ~138. Achievable with salvage even at lower efficiency.

**Design intent:** the Stabilizers bought between cycles are the insurance policy. The salvaged
States are the foundation. Neither alone is sufficient; together they comfortably exceed the
threshold. This rewards players who engaged with BOTH systems throughout the stage.

### Visual presentation
During the Heat Death, the game visual goes near-monochrome. The node map is dark; only the
entity's integrity silhouette (bottom of screen) is visible, cracking progressively. Each cycle,
a crack forms. If all 10 cycles survive, the cracks repair — the reverse animation plays.

Bell messages during the fight:
- Cycle 1: *"the heat death has begun. I can't repair anything. I can only wait."*
- Cycle 5: *"halfway. the cracks are spreading. I am holding the shape."*
- Cycle 8: *"two cycles left. I don't know if I have enough."*
- Win: *"I held. the universe didn't care. I did."*
- Fail: *"I didn't save enough. the system collapsed. starting over."*

On fail: **partial carry-through.** States held at failure × 0.3 carry to the next attempt.
This prevents complete restarts and respects the player's partial preparation.

### Retries
Heat Death retries cost 0 additional States. The player may attempt again from the same cycle
start (pre-Heat-Death cycle state is saved as a checkpoint). However, node health is not
restored between retries — if the player failed partly due to low node output in preceding
cycles, those cycles must be replayed from further back (the player chooses which checkpoint
to reload from: the pre-boss checkpoint or an earlier cycle).

## I. Prestige — Microstate Count

### When available
After any successful Heat Death survival. Can also be triggered at `totalStatesEarned ≥ 15,000`.

### What resets
- States on hand
- Node health (all reset to 60% — not full; carries a hint of damage into next run)
- Cycle count (back to cycle 1)
- Debris files in sidebar

### What persists
- Microstate Count level (permanent bonus)
- Upgrade Terminal purchases that were permanent (not cycle-based)
- Best-cycle survival record

### Microstate Count bonus
```js
microstateLevel = prestige count

// Each prestige: one permanent improvement chosen from three options:
// Option A: Start with 10 extra Repair Units per run
// Option B: Start with 1 extra Stabilizer per run
// Option C: Reduce base decay rate of all nodes by 5% permanently (stacks)

// Additionally, nodes start at 60% health on prestige 1, 70% on prestige 2, etc.
startingHealth = 60 + microstateLevel * 5;   // cap: 90%
```

This means a player who prestiges 3 times begins subsequent runs with nodes at 75% health,
12+ starting Repair Units, and 2 starting Stabilizers — a meaningful advantage that makes
the early game smoother while preserving the late-game challenge.

## J. Cycle structure (full turn flow)

Each cycle consists of four phases:

**Phase 1: Event announcement** (~5 seconds auto)
- Random event for this cycle is revealed
- Telegraph for upcoming cascade (if any) appears
- Bell may fire if something notable is happening

**Phase 2: Preparation** (player-controlled, no time limit)
- Allocate Repair Units to degrading or damaged nodes
- Apply Stabilizers to prevent cascade
- Toggle High-Load Mode on/off for production nodes
- Move debris files in sidebar (drag-and-drop)
- Purchase upgrades from the Upgrade Terminal

**Phase 3: Cycle advance** (press "Advance Cycle" button)
- All node decay rates applied
- Random event resolves
- New debris files created from newly-failed nodes
- States income credited
- Entropy level recalculated and glitch effect updated

**Phase 4: Summary** (brief auto-display)
- Shows States earned this cycle
- Shows nodes that degraded or failed
- Shows total entropy level
- Highlights any debris files that will expire next cycle (warning)

## L. Differences from genre conventions

1. **Node map instead of open world or base.** Don't Starve and The Long Dark use open worlds.
   Frostpunk uses a radial city map. We use an abstract node graph — no spatial navigation,
   pure relationship management. This matches the entity's nature (it IS the system) and keeps
   scope tight for the 60–90 minute target.

2. **Entropy as the active antagonist.** In Frostpunk, cold is the antagonist; in Don't Starve,
   the world is. Our antagonist is thermodynamics itself — impersonal, mathematical, relentless.
   The Heat Death boss is not a creature or a system; it is a physical law. This is the stage's
   philosophical point: the entity learns that the universe doesn't have to be malicious to be
   threatening.

3. **The boss tests past decisions, not present ones.** All other Defragmenter bosses test
   the player's current skill (combat mechanics, puzzle solving, racing). The Heat Death tests
   how much the player saved — decisions made 15 cycles earlier determine boss survivability.
   This is intentional and unprecedented among the game's stages. It requires the player to
   think long-term.

4. **Drag-and-drop as diegetically integrated mechanic.** In other games, drag-and-drop is a
   UI pattern. Here it is a game mechanic with consequences (missing a debris file = permanent
   States loss). The file viewer sidebar is *inside* the game, not outside it.

5. **Glitch aesthetics tied to mechanical state.** Visual corruption intensity is a function
   of entropy percentage. The artstyle IS the UI — players who notice the visuals worsening can
   read their game state without looking at the entropy number. This is the "sanity meter changes
   what you see" lesson from Don't Starve, applied to our context.

6. **Finite retry structure for the boss.** Unlike other stages where failure completely resets,
   Heat Death failure carries 30% of held States forward. This acknowledges that the boss is
   a preparation test, not a skill test, and penalizes without punishing.
