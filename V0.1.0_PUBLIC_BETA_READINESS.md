The Office presets were corrected to include Monaco, which is required by the actual viewer path.
The worker now queues saves, returns results to the initiating client, and includes a unique request
ID in every progress/done/error message. This prevents one tab from reporting another tab's save as
its own. Cache Storage status, not stale localStorage, is authoritative for “Available offline.”

The 45-format run recorded zero off-origin requests. Adversarial HTML, Markdown, EML, EPUB, SVG,
CSS, and generic-image resources are separately tested to ensure default-mode previews cannot fetch
remote URLs. The origin harness itself now compares parsed origins, with regression cases for
userinfo, lookalike hosts, schemes, and ports.

## Defects found, fixes, and regression coverage

The trials did find failures beyond surface-level smoke. In particular, two renderer failures were
only exposed by inspecting nested rendered pixels/state: the PDB molecule was technically present
but visually microscopic, and video metadata could race listener setup and remain stuck at an
unknown duration. Both now have direct regressions.

| Severity | Defect found | Fix | Regression/evidence |
|:---:|---|---|---|
| Critical | HTML/SVG/EML/EPUB and generic-image content could retain remote DOM/CSS resource URLs | centralized DOM/CSSOM sanitization; SVG renderer uses the sanitizer; remote loads blocked before iframe/image use | `html-remote-resources`, `embedded-remote-resources`, Markdown privacy tests; zero request ledger |
| Critical | Offline first-controller save could disappear; cross-tab save broadcasts could let a tab claim another save; stale localStorage could falsely claim readiness | controller queue, worker serialization, initiating-client replies, request correlation, authoritative cache metadata, honest partial/error states | 10-scenario offline harness, including first visit, two tabs, eviction, interruption, full resume |
| High | Office offline presets omitted Monaco despite the production viewer importing it | added dependency to all affected presets and exact closure checks | limited Office preset plus real production XLSX hard-offline reopen |
| Critical | Request-ledger prefix comparisons could accept crafted same-prefix/lookalike URLs | parse and compare exact URL origins | `harness-origin.test.mjs` userinfo/lookalike/port cases |
| High | Dropped-folder content search mixed virtual and dropped-root paths and could miss results | normalize both search and selection paths relative to the dropped root | ebook/Git smoke plus 20,010 virtual entries |
| Critical | Companion browser-origin enforcement relied too heavily on CORS response behavior; hostile actual requests and blind subresources needed pre-handler rejection | exact-origin middleware, cross-site Fetch Metadata guard, token kept separate for mutations | Rust unit/integration and E2E hostile/lookalike/`null` tests proving unchanged config/files |

## Remaining gaps and nonblocking beta risks

These are not hidden by the GO recommendation:

1. **Untested format remainder:** 99 of 144 registered base types were not manually trialed in this
   pass. The sampled 45 deliberately favor complex/high-risk renderers and every required family,
   but this is broad beta qualification, not exhaustive certification.
2. **Browser scope:** automated runtime coverage is Chromium-only under WSL2. Firefox, WebKit/iOS,
   browser-specific private-network restrictions, and production HTTPS-to-loopback behavior remain
   platform/browser follow-ups.
3. **Native platforms:** Windows received an MSVC cross-compile check, not runtime testing; macOS was
   not built or run. Windows NTFS replacement semantics and macOS FSEvents/tray behavior remain open.
4. **Linux desktop integration:** WSLg had no real GNOME/KDE tray host. An XEmbed host exercised the
   application menu, but real panel placement/icon interaction and login/autostart remain unverified.
   The `.deb` was extracted rather than installed, so install/uninstall behavior was not exercised.
5. **Final package visual provenance:** the exact final payload was launched and tested for listener,
   ping, config and watcher SSE. Native-picker/tray screenshots are from the immediately preceding
   locked package; only watcher retry code changed between it and the final package.
6. **Companion trust model:** the server is loopback-only and browser Origin/token guarded, but other
   programs on the same machine can reach loopback and the session token is intentionally obtainable
   from `/ping`. The UI and README now disclose that machine-wide local trust boundary.
7. **Fixture limitations:** the three-page comic is intentionally sparse; FITS and synthetic DICOM
   evidence are metadata-only and do not prove image-plane/pixel rendering. A real-world corpus should
   supplement them during beta.
8. **Accepted low-severity visual observations:** on 390 px PSD, the trailing 100×100 status readout
   is obscured by the Layers pane though controls/composite remain usable; SARIF's 332 px internal
   horizontal scroll range lacks a strong static affordance; optional base Dockerfile/Compose
   summaries concatenate a few labels/values. These did not block the enhanced/default usable paths.
